# Frontend MVP «СПОРИМ»

## Игровой баланс (задача 2)

Страница `/wallet` показывает доступный баланс и историю операций: стартовый бонус,
ставки, выплаты, возвраты. В шапке отображается тот же баланс. Есть фильтры начислений
и списаний, загрузка, пустая история, повторная загрузка и обработка 401/403/ошибок сети.
Баланс обновляется при возвращении в окно и по событию `sporim:wallet-changed`.

По умолчанию включён демонстрационный кошелёк с 1000 баллов стартового бонуса.
Он явно помечен как демо и не изменяет баланс на сервере.
При `VITE_USE_MOCK_API=false` используется только защищённый `GET /api/v1/wallet`.
Пополнение и вывод не реализованы: в текущем OpenAPI для них нет методов.
Авторизация и размещение прогнозов — отдельные задачи.

Интеграция с будущей авторизацией: после успешного входа сохранить `accessToken`
в `sessionStorage` под ключом `sporim.accessToken` и отправить событие:

```ts
sessionStorage.setItem('sporim.accessToken', response.accessToken)
window.dispatchEvent(new Event('sporim:session-changed'))
```

При выходе удалить ключ и отправить то же событие. После успешного размещения
или расчёта прогноза отправить `sporim:wallet-changed`: данные будут заново прочитаны
с сервера. Клиент не начисляет бонусы и не рассчитывает серверный баланс самостоятельно.
Не сохранять токены в `.env`, исходниках или Git.

Проверка: `npm test` и `npm run build`.

Основание: `shared/openapi.yml`, строки 941–953 — «Получить баланс игровых баллов и
историю операций (Ledger)»; строки 625–626 — «При первом входе создаёт пользователя»
и «начисляет стартовый баланс». У YAML нет страниц, поэтому указаны строки.

Реализована первая задача этапа MVP

- каталог событий
- поиск по названию и описанию
- фильтр по категориям
- переключатель «Только активные»
- карточки открытых, ожидающих результат и завершённых событий
- отдельная страница события
- состояния загрузки, пустого результата и ошибки
- адаптивная вёрстка

## Локальный запуск

```bash
npm install
npm run dev
```

После запуска открыть `http://localhost:5173`

Сейчас приложение использует тестовые данные из `src/data/mockEvents.ts`

## Подключение к бэкенду

Создать файл `.env.local`

```env
VITE_API_BASE_URL=http://localhost:5000
VITE_USE_MOCK_API=false
```

Клиент отправляет запросы

- `GET /api/v1/events`
- `GET /api/v1/events/{eventId}`

Форматы данных описаны в `src/types.ts` и соответствуют переданному OpenAPI-контракту MVP

## Проверка production-сборки
